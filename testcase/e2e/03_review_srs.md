# E2E: 復習日の更新（SRS ロジックの反映確認）

**シナリオ:** 復習画面でカードに評価（難しい/普通/簡単）を付け、API 経由で SRS が更新され、次回復習日やダッシュボードの「今日の復習」枚数が変わることを確認する。

## 対象ファイル・URL

- 復習: `app/review/page.tsx` → `/review`
- API: `POST /api/cards/:id/review`, `POST /api/study-records`
- ロジック: `lib/srs.ts` の `calculateNextReview`

## 前提条件

- 認証済み。今日が due のカードが少なくとも1枚ある（シードまたは前ステップで準備）。

---

## TC-E2E-03-01: 復習で「難しい」を選ぶと次のカードまたは完了画面に進む

| 項目 | 内容 |
|------|------|
| 手順 | 1. `/review` を開き、1枚目のカードで「答えを見る」→「難しい」をクリックする。 |
| 期待 | そのカードの SRS が更新され（intervalDays=1, 翌日が nextReviewDate）、次のカードへ進むか、1枚だけの場合は完了画面になる。エラーや白画面にならない。 |
| 検証 | 2枚目が表示される、または「復習完了」「ダッシュボードに戻る」等の表示が出る。ネットワークで `POST /api/cards/:id/review` が 200 で返っていること。 |

**セレクタ例:** 評価ボタンは「難しい」「普通」「簡単」のいずれか。`getByRole('button', { name: /難しい/ })`。

---

## TC-E2E-03-02: 復習で「普通」を選ぶと次回復習日が翌日（初回）または間隔×1.5で更新される

| 項目 | 内容 |
|------|------|
| 手順 | 1. 今日 due のカードで「答えを見る」→「普通」をクリックする。 |
| 期待 | `POST /api/cards/:id/review` で rating=hard が送られ、次回復習日が計算される（初回なら翌日）。次のカードまたは完了画面に進む。 |
| 検証 | 同上。API が 200。必要なら DB または UI で「今日の復習」枚数が1減っていることを確認。 |

> **注意:** UI の「普通」ボタンは API では `rating: "hard"` として送信される。これは SRS の設計上の命名であり、UI ラベルと異なる点に注意。

---

## TC-E2E-03-03: 復習で「簡単」を選ぶと次回復習日が3日後（初回）または間隔×easeFactorで更新される

| 項目 | 内容 |
|------|------|
| 手順 | 1. 今日 due のカードで「答えを見る」→「簡単」をクリックする。 |
| 期待 | 初回カードなら nextReviewDate が約3日後、intervalDays=3 になる。次のカードまたは完了画面に進む。 |
| 検証 | API 200。完了後、ダッシュボードの「今日の復習」枚数が減っている（そのカードが今日 due から外れる）。 |

---

## TC-E2E-03-04: 復習完了後、ダッシュボードの「今日の復習」枚数が反映されている（オプション）

| 項目 | 内容 |
|------|------|
| 手順 | 1. 今日 due が N 枚ある状態でトップを開き、枚数（N）を確認。<br>2. 復習で1枚「簡単」して完了。<br>3. ダッシュボードに戻る。 |
| 期待 | 「今日の復習」が N-1 枚になっている（または 0 枚で「ALL CLEAR!」）。 |
| 検証 | `TodayReviewCard` の枚数表示が減っている。 |

**実装メモ:** ストアと API の同期、およびページリロードやクライアント側の再計算が正しく動いていることの確認。
