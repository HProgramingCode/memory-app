## 1. Vercel 初回セットアップ時の質問への答え

ターミナルで `vercel` を実行すると、いくつか質問されます。迷いやすいものをまとめます。

| 質問 | おすすめの答え | 理由 |
|------|----------------|------|
| Set up and deploy "〜"? | **Y** | このフォルダを Vercel でデプロイするため |
| Want to modify these settings? | **N** | Next.js は自動検出で問題ない。あとからダッシュボードで変更できる |
| Do you want to change additional project settings? | **N** | 環境変数などはあとで Web で設定する |
| Detected a repository. Connect it to this project? | **Y** | 接続すると、`main` に push するたびに自動デプロイされる |

---

## 2. デプロイの反映の仕方

- **ローカルでコミットしただけでは本番には反映されません。**
- `main` ブランチに **push** したタイミングで、Vercel が自動的にビルド・デプロイします。
- 環境変数を追加・変更しただけのときも、**Redeploy**（再デプロイ）しないと反映されません。  
  - Vercel ダッシュボード → Deployments → 対象デプロイの「⋯」→ **Redeploy**

## 3. MissingSecret エラー（認証が動かない）

### 出るメッセージの例

```
[auth][error] MissingSecret: Please define a `secret`.
```

### 原因

**Google OAuth の設定ではなく、Auth.js 用の「秘密鍵」が本番で未設定**なことが原因です。

### 対処手順

1. Vercel ダッシュボード → 対象プロジェクト → **Settings** → **Environment Variables**
2. 次の 2 つを **Production** 用に追加する：

| 名前 | 値 | 補足 |
|------|-----|------|
| `AUTH_SECRET` | 32 文字以上のランダム文字列 | ターミナルで `openssl rand -base64 32` を実行して生成した値を使う |
| `AUTH_URL` | 本番の URL | 例: `https://あなたのアプリ.vercel.app`（`http://localhost:3000` は本番では使わない） |

3. 保存後、**Redeploy** する（または `main` に空コミットで push）。

## 4. 本番に追加する環境変数一覧

ローカルの `.env` にあるものを、**本番用の値に置き換えて** Vercel に登録します。

| 変数名 | 本番で入れる値 | 注意 |
|--------|----------------|------|
| `AUTH_SECRET` | 新規生成したランダム文字列（`openssl rand -base64 32`） | 本番用はローカルと別の値にするのが望ましい |
| `AUTH_URL` | 本番の URL（例: `https://memory-app-xxx.vercel.app`） | ローカルの `http://localhost:3000` のままにしない |
| `AUTH_GOOGLE_ID` | ローカルと同じ Client ID でよい | Google の「リダイレクト URI」に本番 URL を登録しておく |
| `AUTH_GOOGLE_SECRET` | ローカルと同じ Client Secret でよい | 同上 |
| `TURSO_DATABASE_URL` | Turso の URL（ローカルと同じでよい） | 本番で Turso を使う場合 |
| `TURSO_AUTH_TOKEN` | Turso のトークン（ローカルと同じでよい） | 本番で Turso を使う場合 |
| `DATABASE_URL` | 本番で Prisma が参照するなら Turso の接続文字列（`libsql://...`） | 本番で SQLite の `file:./dev.db` は使わない |

**重要**: `.env` の内容（特に `AUTH_GOOGLE_SECRET` や `TURSO_AUTH_TOKEN`）は**秘密情報**なので、Git にコミットせず、Vercel の「環境変数」画面だけで設定してください。

## 5. Preview / Development 環境の環境変数

### Preview（プレビュー環境）

- 各ブランチのデプロイ用。**本番と同じ環境変数を入れておいてよい**です。
- `AUTH_URL` はプレビューごとに URL が変わるため、アプリ側で `VERCEL_URL` から動的に組み立てる実装にしている場合は、Preview 用に特別な設定が不要なことが多いです。
- Google は、本番用の 1 つのクライアントの「リダイレクト URI」に、プレビュー用の URL を追加すれば同じ Client ID/Secret で使えます。

### Development（開発環境）

- Vercel の「Development」は、`vercel dev` などで使うとき用です。
- 普段はローカルの `.env` だけで開発するなら、Vercel の Development 用の環境変数は**必須ではありません**。
- 入れる場合は、`AUTH_URL=http://localhost:3000` などローカル用の値にします。

## 6. Google OAuth：開発と本番で別クライアントは必要？

**別に作る必要はありません。** 最初に認証用に作った **1 つの OAuth 2.0 クライアント（Client ID / Secret）** を、開発と本番の両方で使えます。

やることは **「1 つのクライアントのまま、リダイレクト URI を複数登録する」** だけです。

1. **Google Cloud Console** → 対象プロジェクト → **API とサービス** → **認証情報**
2. 使っている **OAuth 2.0 クライアント ID** を開く
3. **承認済みのリダイレクト URI** に、次のように **両方** を追加する：
   - 開発: `http://localhost:3000/api/auth/callback/google`
   - 本番: `https://あなたの本番ドメイン/api/auth/callback/google`  
     例: `https://memory-app-xxxx.vercel.app/api/auth/callback/google`
4. プレビュー環境でもログインする場合は、  
   `https://*.vercel.app/api/auth/callback/google` を追加できるか確認する（プロダクトによっては、サブドメインごとに 1 本ずつ追加する場合もあります）

## 7. AUTH_URL は本番で変える？

- **ローカルの `.env`** はそのままでよいです（`AUTH_URL="http://localhost:3000"` のまま）。
- **Vercel の本番用環境変数**では、`AUTH_URL` を **本番の URL に必ず変更**します。
  - 例: `https://memory-app-xxxx.vercel.app`（実際の Vercel の本番 URL に合わせる）
- 本番で `AUTH_URL` が未設定や `http://localhost:3000` のままだと、認証後のコールバック先が誤り、ログインできません。

## 8. 500 MIDDLEWARE_INVOCATION_FAILED

### 出るメッセージの例

```
500: INTERNAL_SERVER_ERROR
Code: MIDDLEWARE_INVOCATION_FAILED
```

### 原因

Auth.js のミドルウェアが Vercel の Edge 環境で実行される際、**ホストの検証**で失敗していることが多いです。

### 対処手順

1. Vercel ダッシュボード → 対象プロジェクト → **Settings** → **Environment Variables**
2. 次を追加する：

| 名前 | 値 | 適用 |
|------|-----|------|
| `AUTH_TRUST_HOST` | `true` | Production（必要なら Preview も） |

3. 保存後、**Redeploy** する。

### それでも 500 が出る場合

Vercel の **デプロイログ** で原因を確認します。

- プロジェクト → **Deployments** → 該当デプロイ → **Building** または **Functions** のログ
- または **Logs**（Runtime Logs）で、`MIDDLEWARE_INVOCATION_FAILED` の前後に出ているスタックトレースを確認する

ログに表示されているエラー内容が分かれば、次の対処を検討できます。

- [ ] Vercel の環境変数に `AUTH_SECRET` を追加した（本番用に新規生成）

- [ ] Vercel の環境変数に `AUTH_TRUST_HOST=true` を追加した
- [ ] Google OAuth の「承認済みのリダイレクト URI」に本番のコールバック URL を追加した
- [ ] Turso を使う場合、`TURSO_DATABASE_URL` と `TURSO_AUTH_TOKEN` を Vercel に追加した
- [ ] 環境変数追加・変更後、Redeploy した
