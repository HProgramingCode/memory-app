# ジュニアエンジニアが覚えておく知識（2026-03-17）

## 1. fetch と HTTP エラーの扱い

- **`fetch(url)` は、404 や 403 でも reject しない。** レスポンスが返ってくれば Promise は resolve する。
- そのため、**`res.ok`（status 200–299 のとき true）を必ず確認**し、`!res.ok` のときは `throw new Error(...)` するなどして呼び出し元でエラーとして扱う。
- 確認しないと、4xx/5xx の JSON が「正常な data」として扱われ、UI で誤った表示や「取得に失敗しました」のような汎用メッセージの原因になる。

```ts
// ❌ 悪い例: 403 の body がそのまま data に入る
const fetcher = (url: string) => fetch(url).then((res) => res.json());

// ✅ 良い例: エラー時に throw して SWR の error に渡す
const fetcher = async (url: string) => {
  const res = await fetch(url);
  const body = await res.json();
  if (!res.ok) throw new Error(body?.error || `Error ${res.status}`);
  return body;
};
```

## 2. 管理者機能と環境変数

- 管理者限定の API（例: `/api/admin/reviews`）では、**ログインユーザーのメールが許可リストに含まれるか**で 403 を返す実装がよくある。
- このプロジェクトでは **`ADMIN_EMAILS`**（カンマ区切りのメールアドレス）を `.env` に設定し、一覧に含まれるユーザーのみ管理者として扱う。
- `.env` を変更したら **サーバー（開発サーバー）の再起動**が必要。クライアントのリロードだけでは反映されない。

## 3. 責務分離（features 配下）

- **API Route（`app/api/.../route.ts`）** では、認証・バリデーション・HTTP の入出力に集中する。
- **DB アクセス（Prisma）** は **`features/<ドメイン>/repository.ts`** にまとめ、Route からは `createXxx` や `getXxx` のような関数を呼ぶ形にする。
- こうすると、テストや他 API からの再利用がしやすく、Route が薄く保てる。

## 4. SWR について

- **SWR** は、React 用のデータ取得ライブラリ（Vercel 製）。API からデータを取ってきてキャッシュし、必要に応じて再取得する。
- 使用するには **`npm install swr`** でインストールし、コンポーネント内で **`import useSWR from "swr"`** する。
- **`useSWR(key, fetcher)`** で、第1引数が「どのデータか」のキー（URL など）、第2引数が実際に fetch する関数。戻り値は **`{ data, error, isLoading }`** など。
- 画面遷移は不要。コンポーネントがマウントされると裏で取得し、`data` が変われば再レンダリングされる。フォーカスが戻ったときの再取得もデフォルトで行う。
- **注意:** fetcher で `res.json()` だけしていると、403 などで返る **`{ error: "Forbidden" }` がそのまま `data` に入る**。配列を期待している箇所で `data.map()` を呼ぶと `TypeError: data.map is not a function` になる。**`Array.isArray(data)` で分岐**するか、fetcher 内で `!res.ok` のときに `throw` して `error` 側で扱うようにする。

## 5. 障害調査の進め方（今回の教訓）

- 「通信エラー」と表示されても、**実際は 403 など HTTP エラー**のことがある。
- 調査の手順の例:
  1. ブラウザの開発者ツールの Network タブで、該当 API の **ステータスコード** と **レスポンス body** を確認する。
  2. クライアント側で、**fetcher が res.ok を見ているか**を確認する。
  3. 403 なら、**権限まわり（環境変数・ログインユーザー）** を確認する。
  4. `data.map is not a function` が出た場合は、**レスポンスが配列でない**（例: 403 の `{ error: "Forbidden" }` が data に入っている）可能性を疑い、`Array.isArray(data)` でガードする。
