# 障害対応の原因調査（2026-03-17）

## 事象

管理者用レビュー一覧ページ（`/admin/reviews`）で、次のメッセージが表示される。

- 「レビューの取得に失敗しました。権限またはネットワークを確認してください。」

## 調査結果

### 実際の原因

**ネットワーク障害ではなく、API が 403 Forbidden を返していた。**

1. **API の挙動**  
   `GET /api/admin/reviews` は、管理者でないリクエストに対して **403** と `{ error: "Forbidden" }` を返す（`app/api/admin/reviews/route.ts`）。

2. **403 になる条件**  
   - `.env` に `ADMIN_EMAILS` が未設定  
   - または、ログイン中のユーザーのメールアドレスが `ADMIN_EMAILS` のカンマ区切りリストに含まれていない  

3. **なぜ「取得に失敗」と表示されていたか**  
   - クライアントの fetcher が `fetch(url).then((res) => res.json())` のみで、**HTTP ステータス（res.ok）を確認していなかった**。  
   - 403 の場合もレスポンス body がそのまま `data` に入り、`Array.isArray(data)` が false になる。  
   - その結果、配列が返ってきた場合と区別できず、「取得に失敗しました」のメッセージが表示されていた。

### 結論

- 表示上の「通信エラー」は、**権限不足（403）** によるもの。
- 原因の切り分けがしづらかった要因は、**fetcher が 4xx/5xx をエラーとして扱っていなかった**こと。
