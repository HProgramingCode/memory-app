# 03 — デッキ詳細をリロードすると「デッキが見つかりません」になる

## 事象

`/decks/[deckId]` を**直接開いた状態でリロード**すると、しばらくまたはずっと **「デッキが見つかりません」** のように見える。  
（ダッシュボードは SSR で初期データが入るが、デッキ詳細はクライアントのストア依存だった。）

## 原因は2層あった

### A. DataInitializer（補助的な問題）

[`components/common/DataInitializer.tsx`](../../../components/common/DataInitializer.tsx) が、過去の実装では **`useRef` で「一度だけ fetch」** を止めていた。

- React 18 **Strict Mode（開発時）**の「マウント → アンマウント → 再マウント」で、**ref が true のまま**残り、**2 回目以降フェッチが走らない**ことがある。  
- また API が一瞬失敗したとき **`ref` を戻さず**、**再試行できない**ことがあった。

**対応:** `didFetch` 型の **永続ブロックをやめる**。認証済みのとき effect が走り、**最大 3 回まで短い待ちを挟んでリトライ**。アンマウント時は `cancelled` で **`replaceAll` を打たない**。

### B. Zustand のセレクタ（主因）

[`app/decks/[id]/page.tsx`](../../../app/decks/[id]/page.tsx) で次のように書いていた（概念）:

```ts
const getDeck = useDeckStore((s) => s.getDeck);
const deck = getDeck(id);
```

Zustand（React の `useSyncExternalStore`）は、**セレクタが返した値の参照が変わったとき**に再レンダーする。

- `getDeck` は **常に同じ関数オブジェクト**  
- だから **`decks` が API で埋まっても「値が変わっていない」扱い**で、**画面が更新されない**  
- 初回は `deck === undefined` → 「見つかりません」のまま固定

**対応:** **`s.decks` / `s.cards` の配列参照**を購読し、必要なら `useMemo` で `find` / `filter` する（次節）。

### C. React 19 の警告（派生）

セレクタをこうすると **毎回新しい配列**が返る:

```ts
useCardStore((s) => s.cards.filter((c) => c.deckId === id));
```

`getSnapshot` が **連続で別インスタンス**を返すと、React 19 は **「The result of getSnapshot should be cached」** と警告しうる。

**対応:**

```ts
const allCards = useCardStore((s) => s.cards);
const cards = useMemo(
  () => allCards.filter((c) => c.deckId === id),
  [allCards, id],
);
```

デッキ 1 件も同様に `decks` を購読して `useMemo` で `find`。

## 確認方法

1. ログイン済みで `/decks/有効なUUID` を開く。  
2. **ハードリロード**（Cmd+Shift+R 等）。  
3. 数秒以内に **デッキ名・カード一覧が表示**される。  
4. コンソールに **getSnapshot / infinite loop 系の警告が出ない**。

## 関連しなかったもの

- **SQLite のファイルが消えた**わけではない（別事象。Vercel のローカルファイル DB などは別途 Turso 等が必要）。
